## เปิด/ปิดรับลงทะเบียน (`index.html`)

ทีมงานสามารถเปิด/ปิดรับลงทะเบียนของหน้า `index.html` ได้ตามต้องการ จากหน้า `admin-tickets.html`
แท็บ "คำสั่งซื้อ" จะมีการ์ด **"📝 หน้าลงทะเบียน (สาธารณะ)"** อยู่ใกล้กับการ์ดเปิด/ปิดขายบัตร
กดปุ่ม **"⏸️ ปิดรับลงทะเบียน"** เพื่อปิดชั่วคราว — หน้า `index.html` ของทุกคนจะแสดงข้อความ
"ปิดรับลงทะเบียนชั่วคราว" แทนแบบฟอร์ม (อัปเดตแบบเรียลไทม์ ไม่ต้องแก้โค้ดหรืออัปโหลดไฟล์ใหม่)
กดปุ่ม **"🟢 เปิดรับลงทะเบียน"** เพื่อเปิดรับลงทะเบียนอีกครั้ง

> ค่าเริ่มต้น (ยังไม่มีการตั้งค่าใน Firestore) คือ **เปิดรับลงทะเบียน**
> แท็บ "รายชื่อผู้ร่วมงาน" ของ `index.html` ยังเข้าดูได้ตามปกติแม้ปิดรับลงทะเบียน

## โหมด "เปิดขายเร็วๆ นี้" (Coming Soon) สำหรับทดสอบก่อนเปิดขายจริง

ตอนนี้หน้า `tickets.html` ถูกตั้งค่าให้ **คนทั่วไปเห็นแค่หน้า "เปิดจำหน่ายบัตรเร็วๆ นี้"** เท่านั้น
ระบบซื้อบัตรจริงจะถูกซ่อนไว้ จนกว่าทีมงานจะกดเปิดขายจากหน้าหลังบ้าน

- **ทีมงานเข้าทดสอบระบบจริงได้** 2 วิธี (ใช้ได้แม้ยังไม่เปิดขาย):
  1. กดลิงก์ "สำหรับทีมงาน: เข้าทดสอบระบบ" ที่มุมล่างของหน้า Coming Soon แล้วกรอกรหัส:
     **`ptpt-preview-2569`**
  2. หรือเข้าผ่านลิงก์ที่แนบรหัสไปเลย:
     `https://<username>.github.io/alumni-reunion/tickets.html?preview=ptpt-preview-2569`

  เมื่อกรอกรหัสถูกครั้งหนึ่งแล้ว เบราว์เซอร์/อุปกรณ์เครื่องนั้นจะจำไว้ (localStorage)
  ไม่ต้องกรอกซ้ำในครั้งถัดไป

- **เมื่อพร้อมเปิดขายจริงให้คนทั่วไป**: ไปที่หน้า `admin-tickets.html` แท็บ "คำสั่งซื้อ"
  จะมีการ์ด **"🛒 หน้าซื้อบัตร (สาธารณะ)"** อยู่ด้านบนสุด กดปุ่ม
  **"🚀 เปิดขายให้คนทั่วไป"** — หน้า `tickets.html` ของทุกคนจะเปลี่ยนจาก Coming Soon
  เป็นหน้าซื้อบัตรจริงทันที (อัปเดตแบบเรียลไทม์ ไม่ต้องแก้โค้ดหรืออัปโหลดไฟล์ใหม่)
  หากต้องการปิดการขายชั่วคราว (เช่น บัตรหมด) กดปุ่ม **"⏸️ ปิดการขาย"** ได้จากการ์ดเดียวกัน

> หมายเหตุ: รหัส `ptpt-preview-2569` เป็นเพียงการกันไม่ให้คนทั่วไปเข้าถึงโดยบังเอิญก่อนวันเปิดขาย
> ไม่ใช่ระบบความปลอดภัยระดับสูง หากรหัสหลุดให้เปลี่ยนค่า `PREVIEW_CODE` ในไฟล์ `tickets.html`

## วิธีใช้งานสำหรับผู้ซื้อ (`tickets.html`)

1. เลือกจำนวนบัตรแต่ละประเภท ระบบคำนวณยอดรวมอัตโนมัติ
   - **บัตรผู้ใหญ่**: ใบที่ 1 ใช้ชื่อผู้สั่งซื้อ หากเลือกมากกว่า 1 ใบ ระบบจะให้กรอก
     **ชื่อ-นามสกุลผู้ถือบัตรเพิ่มเติม** (เช่น แฟน) สำหรับใบที่ 2 เป็นต้นไป
   - **บัตรเด็ก / เด็กเล็ก-เบบี๋**: ต้องกรอกชื่อ-นามสกุลผู้ถือบัตรทุกใบ (ตั้งแต่ใบที่ 1)
     เนื่องจากมักเป็นคนละคนกับผู้สั่งซื้อ
   - ชื่อที่กรอกจะถูกพิมพ์บนบัตรของแต่ละคนในหน้าตรวจสอบ/ดาวน์โหลด
2. กรอกชื่อ-เบอร์โทร-**รุ่น**ของผู้สั่งซื้อ (บังคับกรอก) และเลือกเครื่องดนตรีที่เคยเล่น (ถ้ามี)
   แล้วกด "สั่งซื้อบัตร" → ระบบสร้างรหัสคำสั่งซื้อ (Order Code)
3. สแกน QR PromptPay เพื่อโอนเงิน แล้วแนบรูปสลิปในหน้าเดียวกัน
4. รอทีมงานตรวจสอบ และรอประธานอนุมัติขั้นสุดท้าย (ปกติไม่เกิน 1-2 วัน)
5. กลับมาที่แท็บ "ตรวจสอบ/ดาวน์โหลดบัตร" → กรอกเบอร์โทรเดิม → เมื่อสถานะเป็น "ชำระเงินแล้ว"
   จะมีปุ่มดาวน์โหลดบัตร (1 ใบ/คน) เป็นไฟล์รูปภาพ พร้อม QR สำหรับเช็คอินหน้างาน
   — บนบัตรจะแสดง **รุ่น** และ **เครื่องดนตรี** ที่กรอกไว้ด้วย

## วิธีใช้งานสำหรับทีมงาน (`admin-tickets.html`)

1. เปิดหน้า `admin-tickets.html` แล้วใส่รหัสผ่าน — ระบบมี **2 ระดับสิทธิ์**:
   - **รหัสทีมงาน** (เหรัญญิก/ทะเบียน): **`ptpt-ticket-2569`**
     ใช้ตรวจสลิป/ข้อมูล แต่ยังไม่สามารถอนุมัติขั้นสุดท้ายได้
   - **รหัสประธาน** (ผู้มีสิทธิ์อนุมัติขั้นสุดท้ายเพียงคนเดียว): **`ptpt-president-2569`**
   - แนะนำให้เปลี่ยนรหัสทั้งสองก่อนใช้งานจริง โดยแก้ค่า `ADMIN_PASS` และ `CHAIRMAN_PASS`
     ในไฟล์ `admin-tickets.html` — **ควรให้รหัสประธานรู้คนเดียว** อย่าแชร์ให้ทีมงานคนอื่น
2. แท็บ **"คำสั่งซื้อ"** — ขั้นตอนอนุมัติ 2 ชั้น เพื่อป้องกันการอนุมัติพลาด/ใจอ่อนจนขาดทุน:
   - ดูยอดขายรวม, จำนวนบัตรแต่ละประเภท, จำนวนที่รอตรวจสอบ
   - คลิกรูปสลิปเพื่อดูภาพขยาย
   - **ทีมงาน** ตรวจสลิป แล้วกด **"✅ ตรวจสอบแล้ว (ส่งให้ประธานอนุมัติ)"**
     → สถานะเปลี่ยนเป็น "🟡 ตรวจสอบแล้ว รอประธานอนุมัติ" (ยังดาวน์โหลดบัตรไม่ได้)
   - **ประธาน** (ผู้ใช้รหัสประธาน) จะเห็นปุ่ม **"⭐ อนุมัติ (ขั้นสุดท้าย)"** บนรายการที่ทีมงานตรวจสอบแล้ว
     → กดเพื่ออนุมัติจริง ผู้ซื้อจะดาวน์โหลดบัตรได้ทันที
   - ประธานยังสามารถกด **"⭐ อนุมัติทันที (ประธาน)"** เพื่ออนุมัติได้โดยไม่ต้องรอทีมงานตรวจสอบก่อนก็ได้
   - กด **"ไม่ผ่าน"** หากสลิปไม่ถูกต้อง (ผู้ซื้อจะเห็นสถานะนี้และต้องติดต่อทีมงาน)
   - กด **"↩️ ย้อนกลับเป็นรอตรวจสอบ"** หากต้องการแก้ไขรายการที่ตรวจสอบไปแล้วก่อนส่งให้ประธาน
3. แท็บ **"เช็คอินหน้างาน"**
   - กด "เริ่มสแกน" เพื่อเปิดกล้องสแกน QR บนบัตรของผู้เข้าร่วม
   - ระบบจะตรวจสอบว่าบัตรนี้ชำระเงินแล้วหรือยัง และยังไม่เคยเช็คอินมาก่อน
   - หากกรอกรหัสบัตรด้วยมือ ใช้ช่อง "กรอกรหัสบัตรด้วยตนเอง" ได้เช่นกัน

## การตั้งค่า Firestore (ต้องทำก่อนใช้งานจริง)

ระบบนี้ใช้ Firebase project เดิม (`alumni-reunion-ptpt`) เพิ่ม collection ใหม่ 2 ตัว:

- `ptpt_ticket_orders` — เก็บคำสั่งซื้อแต่ละรายการ (ชื่อ, เบอร์, เครื่องดนตรี, จำนวนบัตร, ยอดเงิน, สลิป, สถานะ)
- `ptpt_tickets` — เก็บบัตรแต่ละใบแยกรายใบ (ใช้รหัสบัตรเป็น Document ID, ไว้สแกนเช็คอิน)
- `ptpt_config` — เก็บค่าตั้งค่าระบบ เช่น สถานะเปิด/ปิดขายบัตร (เอกสาร `ticket_sales`)

ไปที่ [Firebase Console](https://console.firebase.google.com/) → เลือกโปรเจกต์ `alumni-reunion-ptpt`
→ Firestore Database → Rules แล้วเพิ่ม/ปรับกฎสำหรับ collection ใหม่ เช่น:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    match /alumni_reunion_ptpt/{doc} {
      allow read, write: if true;
    }

    match /ptpt_ticket_orders/{doc} {
      allow read, write: if true;
    }

    match /ptpt_tickets/{doc} {
      allow read, write: if true;
    }

    match /ptpt_config/{doc} {
      allow read, write: if true;
    }
  }
}
```

> หมายเหตุ: กฎข้างบนเปิดให้อ่าน/เขียนได้แบบสาธารณะเพื่อความง่าย (เหมาะกับงานเล็ก/ระยะสั้น)
> รหัสผ่านทีมงานในหน้า admin เป็นเพียงการกันไม่ให้คนทั่วไปเข้าหน้าหลังบ้านโดยบังเอิญเท่านั้น
> ไม่ใช่การรักษาความปลอดภัยระดับฐานข้อมูล หากต้องการความปลอดภัยสูงขึ้นควรทำ Firebase Authentication เพิ่มเติม

## Security Headers

ทุกหน้า (`index.html`, `tickets.html`, `admin-tickets.html`) มี
`<meta http-equiv="Content-Security-Policy">` และ `<meta name="referrer">`
ฝังไว้ใน `<head>` เพื่อจำกัดแหล่งที่มาของสคริปต์/สไตล์/รูปภาพที่อนุญาต และลดความเสี่ยง XSS

> หมายเหตุ: GitHub Pages เป็น static hosting ไม่สามารถตั้งค่า HTTP response header
> เช่น `X-Frame-Options`, `X-Content-Type-Options`, `Permissions-Policy` ได้โดยตรง
> (ตั้งได้เฉพาะผ่าน `<meta>` ซึ่งรองรับแค่บางหัวข้อ เช่น CSP/Referrer-Policy)
> หากต้องการ header ครบถ้วนระดับ A ต้องย้ายไปโฮสต์บนบริการที่ตั้งค่า header เองได้
> เช่น Cloudflare Pages / Netlify / Vercel (ใช้ไฟล์ `_headers` หรือ `vercel.json`)

## วิธีเผยแพร่ออนไลน์ด้วย GitHub Pages (ฟรี)

1. สร้างบัญชี GitHub (ถ้ายังไม่มี) ที่ https://github.com
2. สร้าง Repository ใหม่ เช่น `alumni-reunion`  (ตั้งเป็น Public)
3. อัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (`index.html`, `tickets.html`, `admin-tickets.html`, โฟลเดอร์ `assets/`) ขึ้น repo
   - ผ่านเว็บ: หน้า repo → "Add file" → "Upload files" → ลากไฟล์/โฟลเดอร์ทั้งหมดวาง → Commit
   - หรือผ่าน Git command line:
     ```bash
     cd alumni-reunion
     git init
     git add .
     git commit -m "Initial commit: alumni reunion ticket system"
     git branch -M main
     git remote add origin https://github.com/<username>/alumni-reunion.git
     git push -u origin main
     ```
4. เปิดใช้งาน GitHub Pages:
   - ไปที่ repo → **Settings** → **Pages**
   - หัวข้อ "Build and deployment" → Source เลือก **"Deploy from a branch"**
   - Branch เลือก **`main`** / โฟลเดอร์ **`/ (root)`** → กด Save
   - รอ 1-2 นาที จะได้ลิงก์เว็บไซต์รูปแบบ:
     ```
     https://<username>.github.io/alumni-reunion/
     ```
5. ลิงก์ที่ใช้แชร์:
   - หน้าซื้อบัตร (สำหรับผู้เข้าร่วมงาน):
     `https://<username>.github.io/alumni-reunion/tickets.html`
   - หน้าหลังบ้าน (สำหรับทีมงานเท่านั้น — อย่าแชร์ลิงก์นี้สาธารณะ):
     `https://<username>.github.io/alumni-reunion/admin-tickets.html`
   - หน้าลงทะเบียนสำรวจยอด:
     `https://<username>.github.io/alumni-reunion/index.html`

## โครงสร้างข้อมูลบัตร (สำหรับอ้างอิง)

แต่ละใบบัตรมีรหัสไม่ซ้ำกัน ขึ้นต้นด้วยตัวอักษรบอกประเภท:
- `A......` = ผู้ใหญ่
- `C......` = เด็ก
- `B......` = เด็กเล็ก/เบบี๋

รหัสนี้จะถูกเข้ารหัสเป็น QR Code บนบัตร E-Ticket และใช้สแกนเช็คอินหน้างาน
